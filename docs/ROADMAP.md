# VINGO — Дорожная карта

Статус продукта подбора автозапчастей по VIN/госномеру. Обновляется по мере работы.

## Архитектура
- Монорепо на Bun: `backend` (Hono + Prisma + PostgreSQL), `webapp` (Vite + React + TanStack + shadcn), `mobile` (Expo, standalone), `packages/contracts` (Zod), `website` (Astro).
- Единое backend-ядро для веба, Telegram-бота и мобильного.
- Слои провайдеров (мок сейчас → реальные API позже без переписывания): `CatalogProvider` (VIN→OEM), `SupplierProvider` (номер→предложения), `PlateProvider` (госномер→VIN), `PaymentProvider` (мок + ЮKassa).
- Деньги в копейках (int) + валюта. Локальная БД — нативный PostgreSQL 18 (:5432).

## ✅ Реализовано

### Этап 1 — Поиск
- VIN → авто, госномер → VIN (с нормализацией латиницы→кириллицы), поиск запчастей, предложения.
- Раскладка по 3 тирам «Эконом / Оптимальный / Оригинал» (`tiering.ts`).

### Этап 2 — Кабинет (БД + авторизация)
- Авторизация (refresh-токены, `requireAuth`).
- Гараж (сохранённые авто), корзина (цена авторитетна с сервера), заказы.
- Жизненный цикл заказа: `DRAFT → PLACED → PAID → PROCESSING → READY → COMPLETED` (+ `CANCELLED`), карта переходов в контрактах.

### Этап 3 — Оплата
- Мок работает end-to-end (`/pay`), `YooKassaPaymentProvider` готов (активируется `YOOKASSA_*`).
- Идемпотентность, авто-переход заказа в PAID, webhook.

### Этап 4 — Telegram-бот
- Long-polling, без новых зависимостей, переиспользует `CatalogService`. Поиск по VIN/госномеру → тиры.

### Этап 5 — Мобильное (Expo)
- MVP: вход + поиск (VIN/госномер) + тиры. Запуск на телефоне через Expo Go.

### Этап 6 — Перенос из прототипа (2026-09-01)

Python-прототип [vitogrand-ai/vingo](https://github.com/vitogrand-ai/vingo) заморожен;
его наработки перенесены сюда. Что именно:

- **Словарь автожаргона** (`backend/src/catalog/part-jargon.ts`) — 1015 форм →
  622 канонических термина. Подключён в `CatalogService.searchParts`, поэтому
  «гранатку» и «воздухан» одинаково понимают веб, бот и мобильное. Ответ поиска
  дополнен полем `resolvedQuery` — по какому термину реально нашлось.
- **Каталог PartsAPI/TecDoc** (`backend/src/catalog/partsapi-provider.ts`) —
  боевая интеграция (не скелет): VIN → carId → дерево товарных групп на русском →
  применимые артикулы. Включается `PARTSAPI_KEY`. ⚠️ Нужен российский IP.
- **Фото-VIN** (`backend/src/bot/vin-ocr.ts`) — снимок шильдика/ПТС → VIN через
  Claude Vision по уже имеющемуся `ANTHROPIC_API_KEY`.
- **Голосовые** (`backend/src/bot/voice-transcribe.ts`) — расшифровка через
  OpenAI Whisper по `OPENAI_API_KEY`; без ключа бот просит написать текстом.
- **Регламент ТО** (`backend/src/garage/service-intervals.ts`) — команда `/то <пробег>`
  в боте показывает просроченное и ближайшее. Признак просрочки исправлен
  относительно прототипа: там он не срабатывал никогда (следующая точка сетки
  всегда впереди пробега), теперь просрочка считается от пробега последнего ТО.
- **Брендбук** (`brand/`) — логотипы, иконки, токены. Фавикон и знак применены;
  палитра намеренно не менялась, см. `brand/README.md`.

Не переносилось осознанно: адаптеры поставщиков EuroAuto и Автоконтинент из
прототипа — это пустые каркасы без реальных HTTP-вызовов, переносить нечего.
