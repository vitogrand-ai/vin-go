# VINGO — Дорожная карта

Статус продукта подбора автозапчастей по VIN/госномеру. Обновляется по мере работы.

## Архитектура
- Монорепо на Bun: `backend` (Hono + Prisma + PostgreSQL), `webapp` (Vite + React + TanStack + shadcn), `mobile` (Expo, standalone), `packages/contracts` (Zod), `website` (Astro).
- Единое backend-ядро для веба, Telegram-бота и мобильного.
- Слои провайдеров (мок сейчас → реальные API позже без переписывания): `CatalogProvider` (VIN→OEM), `SupplierProvider` (номер→предложения), `PlateProvider` (госномер→VIN), `PaymentProvider` (мок + ЮKassa).
- Деньги в копейках (int) + валюта. Наценка — в базисных пунктах (`markupBps`, 10000 = 100%). Локальная БД — нативный PostgreSQL 18 (:5432).
- **Продуктовая модель (с 2026-09-03):** VINGO — рабочее место приёмщика небольшого автосервиса.
  Каждый пользователь состоит в **организации (СТО)**: общий гараж машин клиентов, клиенты,
  заказы и наценка. Роли: платформенная `USER/OPERATOR` (оператор = сотрудник VINGO: видит все
  заказы, ведёт их по жизненному циклу, отвечает на заявки эксперту) и внутри СТО `OWNER/MEMBER`
  (владелец меняет настройки и наценку). Позиция заказа хранит **закупочную** цену (что платит
  СТО, по ней идёт оплата и чек) и **цену для клиента** (закуп × наценка, правится вручную) —
  из них считаются смета и маржа.

## ✅ Реализовано

### Этап 1 — Поиск
- VIN → авто, госномер → VIN (с нормализацией латиницы→кириллицы), поиск запчастей, предложения.
- Раскладка по 3 тирам «Эконом / Оптимальный / Оригинал» (`tiering.ts`).

### Этап 2 — Кабинет (БД + авторизация)
- Авторизация (refresh-токены, `requireAuth`).
- Гараж (сохранённые авто), корзина (цена авторитетна с сервера), заказы.
- Жизненный цикл заказа: `DRAFT → PLACED → PAID → PROCESSING → READY → COMPLETED` (+ `CANCELLED`), карта переходов в контрактах.

### Этап 3 — Оплата
- Мок работает end-to-end (`/pay`), `YooKassaPaymentProvider` готов (активируется `YOOKASSA_*`).
- Идемпотентность, авто-переход заказа в PAID, webhook.

### Этап 4 — Telegram-бот
- Long-polling, без новых зависимостей, переиспользует `CatalogService`. Поиск по VIN/госномеру → тиры.

### Этап 5 — Мобильное (Expo)
- MVP: вход + поиск (VIN/госномер) + тиры. Запуск на телефоне через Expo Go.

### Этап 6 — Перенос из прототипа (2026-09-01)

Python-прототип [vitogrand-ai/vingo](https://github.com/vitogrand-ai/vingo) заморожен;
его наработки перенесены сюда. Что именно:

- **Словарь автожаргона** (`backend/src/catalog/part-jargon.ts`) — 1015 форм →
  622 канонических термина. Подключён в `CatalogService.searchParts`, поэтому
  «гранатку» и «воздухан» одинаково понимают веб, бот и мобильное. Ответ поиска
  дополнен полем `resolvedQuery` — по какому термину реально нашлось.
- **Каталог PartsAPI/TecDoc** (`backend/src/catalog/partsapi-provider.ts`) —
  боевая интеграция (не скелет): VIN → carId → дерево товарных групп на русском →
  применимые артикулы. Включается `PARTSAPI_KEY`. ⚠️ Нужен российский IP.
- **Фото-VIN** (`backend/src/bot/vin-ocr.ts`) — снимок шильдика/ПТС → VIN через
  Claude Vision по уже имеющемуся `ANTHROPIC_API_KEY`.
- **Голосовые** (`backend/src/bot/voice-transcribe.ts`) — расшифровка через
  OpenAI Whisper по `OPENAI_API_KEY`; без ключа бот просит написать текстом.
- **Регламент ТО** (`backend/src/garage/service-intervals.ts`) — команда `/то <пробег>`
  в боте показывает просроченное и ближайшее. Признак просрочки исправлен
  относительно прототипа: там он не срабатывал никогда (следующая точка сетки
  всегда впереди пробега), теперь просрочка считается от пробега последнего ТО.
- **Брендбук** (`brand/`) — логотипы, иконки, токены. Фавикон и знак применены;
  палитра намеренно не менялась, см. `brand/README.md`.

Не переносилось осознанно: адаптеры поставщиков EuroAuto и Автоконтинент из
прототипа — это пустые каркасы без реальных HTTP-вызовов, переносить нечего.

### Этап 7 — Рабочее место автосервиса (2026-09-03)

Сделано после аудита продукта (главные пробелы: выдуманные цены без пометки, платный декод VIN
на каждый поиск, отсутствие организации/клиентов/наценки, тупик «ничего не найдено», потеря
контекста бота при рестарте).

- **Честность про данные.** Ответы `/api/catalog/search` и `/offers` несут `source`
  (`{names, demo}`), `GET /api/catalog/status` показывает подключённые источники. Веб и бот
  помечают демо-цены предупреждением — приёмщик не назовёт клиенту выдуманную сумму.
- **Кэш расшифровки VIN** в таблице `vin_decodes` (`CachingCatalogProvider`, 60 дней): повторный
  поиск по той же машине не тратит квоту parts-catalogs и $0.15 у 17vin, переживает рестарт и
  общий для API и бота. Включается только при боевом каталоге и доступной БД.
- **Организация (СТО) и сотрудники.** `Organization` + `User.orgId/orgRole`; регистрация без
  кода создаёт свой автосервис (владелец), с кодом приглашения — вход сотрудником. Гараж,
  клиенты и заказы общие внутри СТО и невидимы другим СТО (проверено интеграционными
  тестами). Старым пользователям без организации она создаётся при первом обращении, их
  гараж и заказы переезжают в неё. Роуты `/api/org` (настройки, код приглашения, переход по коду).
- **Клиенты автосервиса** (`Customer`, `/api/customers`): имя, телефон, заметка. Авто в гараже
  получило госномер, пробег и владельца (`/api/vehicles/update`); привязка корзины к авто из
  гаража подставляет клиента. В смету печатаются автосервис, клиент и машина.
- **Наценка и цена для клиента.** `Organization.defaultMarkupBps`, у позиции `saleAmount` и
  `markupBps`; `POST /api/cart/items/sale-price` — ручная цена. DTO заказа: `salePrice`,
  `saleLineTotal`, `saleTotal`, `marginTotal`, `number` (сквозной номер), `customer`.
  Корзина показывает закуп / клиенту / маржу, карточка заказа печатает «Смету для клиента»
  без закупа. Оплата и чек 54-ФЗ по-прежнему на закупочную сумму.
- **Заявки эксперту** (`ExpertRequest`, `/api/experts/requests`) — человек в цикле: в пустой
  выдаче веб и бот предлагают «Спросить эксперта», оператор платформы отвечает текстом и
  каталожными номерами в разделе «Эксперт», автор получает push/Telegram и сразу видит
  предложения по номерам. Это закрывает пробел покрытия каталогов без внешних ключей.
- **Бот.** Сессии чатов в таблице `bot_sessions` (`PrismaSessionStore`) — VIN не теряется при
  деплое; `/garage` показывает машины автосервиса кнопками (госномер · название · клиент) и
  подставляет VIN; кнопка «Спросить эксперта» в пустой выдаче; в сообщениях — номер заказа.
- **Cron `auth:cleanup`** — чистка отозванных/просроченных сессий, кодов привязки, просроченного
  кэша VIN и старых сессий бота. Запускать раз в сутки.
- **Год авто стал nullable** по всей цепочке (контракт, `Vehicle.year`, провайдеры, веб, бот,
  мобильное): европейские VIN год не кодируют, и 17vin отдавал «Год 0». Для 17vin год
  берётся из конца описания модели («… Dynamic Type 2019»), составные марки приводятся к
  читаемому виду («Mercedes-benz» → «Mercedes-Benz»).

**Диагноз прода 03.09.2026 по скриншотам заказчика.** На VPS задан только 17vin (нет
`PARTSCATALOGS_API_KEY`, `PARTSAPI_*`, `ANTHROPIC_API_KEY`, `ABCP_*`), а поиск деталей 17vin
(операция 5107) сломан на их стороне со 2 сентября: любой запрос («капот», «колодки передние»)
даёт «ничего не найдено», Citroën российской сборки (Z8T…) 17vin не знает — при этом менеджер
parts-catalogs подтвердил, что у них этот VIN открывается. Первое действие: вписать
`PARTSCATALOGS_API_KEY` в `/opt/vingo/app/backend/.env` и перезапустить `vingo-api` и
`vingo-tgbot`; после деплоя проверка — `GET /api/catalog/status` должен показать
`catalog.names = ["partscatalogs","vin17"]`. Параллельно — вопрос менеджеру 17vin про 5107.

Не сделано осознанно: аккаунты поставщиков на организацию (модель Ta-Dam), заказ-наряд с
работами и оплатой при выдаче, история статусов, Telegram-first регистрация без email,
кэш предложений в БД — см. «Предстоит».
