# Адаптеры каталогов и поставщиков

## Правило (владелец продукта, 16.09.2026)

**Адаптер обязан забирать из источника всё, что источник умеет отдавать по запросу мастера, и
доводить до экрана — в боте, в вебе и в мобильном.** Не «минимум, чтобы поиск отвечал», а всё,
что помогает опознать деталь и принять решение.

Повод для правила: 17vin присылал схему узла и номер выноски в каждом ответе поиска несколько
недель подряд, а адаптер эти поля молча отбрасывал. Мастер видел список названий без картинки и
не мог понять, ту ли деталь ему предлагают. Ошибка была не в источнике и не в продукте — в
адаптере, который взял три поля из двадцати.

Правило действует и на путь входа: VIN, госномер, фото шильдика, фраза в чате — если источник
умеет по такому входу отвечать, адаптер обязан это поддержать.

## Чеклист нового адаптера

Прежде чем считать адаптер готовым:

1. **Прочитать документацию источника целиком** — список ВСЕХ операций, не только тех, что
   нужны для первого запроса. Выписать, какие ещё входы (номер, фото, госномер) и какие ещё
   данные (замены, количество, цена дилера, применимость) источник умеет.
2. **Сопоставить каждое поле ответа с контрактом.** Поле, которое не попало в `Part`/`Offer`/
   `Vehicle`, — это осознанное решение, а не забывчивость: либо мапим, либо пишем в комментарии,
   почему нет.
3. **Проверить живым вызовом, а не по документации.** Документация 17vin предлагает для схем
   оп. 4005 — на боевом аккаунте она не работает вовсе, а работает недокументированная для этого
   оп. 5105. Правило: в комментарии адаптера — то, что подтверждено вызовом, с датой.
4. **Довести до экрана.** Поле, которое приходит в API, но не показано в боте и вебе, продукту
   не помогло. Изменение контракта тянет за собой бот, webapp и мобильное — это часть работы.
5. **Добавить случай в корзину** `bun run --cwd backend catalog:cases` с ожиданием на новое поле
   (`scheme`, `position` и т. п.), чтобы пропажу заметил прогон, а не мастер.
6. **Проверить на машине ИЗ ДРУГОЙ ГРУППЫ каталога.** Источник редко однороден: у 17vin база то
   китайская, то английская, у parts-catalogs дерево названий локализовано не для всех марок.
   Термин или разбор ответа, проверенный на одной машине, на соседней может молчать —
   `bun run --cwd backend catalog:terms` меряет это числом и валится, когда словарь не покрывает
   каталог (эталоны — по машине на каждую языковую группу, список в скрипте не сокращается).

## Что источники умеют и что мы берём

Сверено по документации и живыми вызовами, 16.09.2026. Дыры — это список работ, а не жалоба.

### 17vin (китайский EPC, боевой)

| Возможность | Операция | Берём |
|---|---|---|
| Декод VIN | 3001 | да |
| Поиск детали по названию | 5107 | да |
| Схема узла, выноска, идентификатор узла | в ответе 5107 | да, с 16.09.2026 |
| Весь узел по схеме | 5105 `action=part` | да, с 16.09.2026 |
| Координаты выносок на картинке (`all_img_hotspots`) | 5105 | да, с 16.09.2026 — обводка детали на схеме в вебе; с 17.09.2026 выноски в вебе нажимаются (выбор соседней детали узла); в боте обводки пока нет (нужна библиотека рисования) |
| Количество на машину (`qty`) | 5107/5105 | да, с 16.09.2026 |
| Номер замены (`replacement`) | 5107/5105 | да, с 16.09.2026 |
| Примечание (`remark`: «для мотора 1GRFE», «NO.2») | 5107/5105 | да, с 16.09.2026 |
| Период применимости (`begin_date`/`end_date`) | 5107/5105 | да, с 16.09.2026 |
| Замены по номеру (interchange) | 4004 | **нет** |
| Цена у официального дилера | 4006 | да, с 16.09.2026 — **платная за каждый вызов** (0,03 ¥, повторы тоже), поэтому за суточным кэшем |
| Распознавание VIN с фото шильдика/СТС | 3002, 3003 | нет — фото уже распознаётся через Claude Vision (`bot/vin-ocr.ts`); 17vin OCR — запасной путь, если на сервере нет `ANTHROPIC_API_KEY` |
| Все названия деталей по VIN (строка через `@`) | 5110 | **нет** — основа локального нечёткого поиска |
| Все OE-номера по VIN | 5109 | **нет** |
| Подсказки поиска | 5112 | **нет** |

Что платно, а что нет (живой замер баланса, 16.09.2026): декод уже оплаченного VIN, поиск 5107,
узел 5105 и запрос баланса баланс не трогают; цена дилера 4006 списывает за каждый вызов.
Новую операцию перед включением в продукт проверять так же — баланс до и после.

Ограничение источника, обходов не найдено: по `chery` и `greatwall` любой запрос деталей по VIN
отвечает `vin码解码失败` при успешном декоде — 5107, 5109 и 5110 одинаково. То есть локальный
поиск по полному списку названий китайские бренды не спасёт.

Каталоги 17vin разноязычны, и это решает исход поиска. У китайских марок база на китайском
EPC-языке, у импортных (`jaguar`, `subaru`, `benz`, `audi_vw`) — на английском, с машинным
китайским переводом рядом. Поэтому русский запрос идёт двумя проходами: сперва китайским
термином словаря `part-terms`, затем — если он не нашёл ничего — английским (живьём 18.09.2026,
Jaguar XF SAJAA04M6FPU46282: `机油滤清器` даёт ноль, деталь зовётся `Oil filter`; так
промахивались 36 терминов словаря из 68, то есть по такой машине поиск молчал почти всегда).

Латинский запрос каталог не фильтрует вовсе: на любое слово он отдаёт весь подходящий VIN
список целиком (2272 записи на том же Jaguar — одинаково на «oil filter» и на «zzzzqqq»).
Английский проход поэтому устроен как выгрузка со своим отбором:

* термин ищется ЦЕЛОЙ ФРАЗОЙ, а термины перебираются в порядке словаря, от узкого к родовому,
  и выдачу даёт первый попавший — иначе родовое `pad` приносит накладки бампера и подушки
  сидений вместо колодок;
* потолок `VIN17_MAX_PARTS` накладывается ПОСЛЕ отбора: до него нужная деталь стояла 2012-й в
  выгрузке и в сотню не попадала;
* первой строкой идёт деталь, названная ровно термином, затем та, чьё название им
  заканчивается (в английском главное слово — последнее: `Lead-acid battery` — аккумулятор,
  `Ion battery charger` — зарядное устройство).

Чего проход не умеет: если каталог называет деталь родовым словом, а термин словаря — тоже
одно родовое слово, первой строкой может встать сосед (`Starter ring` на запрос «стартер»).
Ловится это только живым случаем — поэтому каждая такая жалоба идёт в корзину
`catalog:cases`, а промахи пишутся в журнал меткой `[catalog:miss]`.

### parts-catalogs (мировой OEM, боевой)

Берём номер, название, категорию, схему узла, номер позиции. Ключ привязан к IP сервера,
поэтому проверять — на VPS.

**Не берём** координаты выносок: в корне ответа `parts2` лежит `positions`
(`{number, coordinates: [x, y, w, h]}`), а в `Part.schemeHotspot` они не попадают. Поэтому на
схемах этого каталога деталь узла выбирается из списка рядом со схемой, а не нажатием на номер.
Прежде чем мапить — сверить живым вызовом, в пикселях какой картинки даны координаты
(превью `/r/300x430/` или оригинал 787×1076): адаптер отдаёт адрес оригинала.

С 17.09.2026 берём и то, чем исполнения одной позиции различаются (`partDetails` в адаптере),
из `description` и `notice` детали в ответе `parts2`:

| Что | Откуда (живьём) | Куда |
|---|---|---|
| Ёмкость и ток АКБ, сторона фары, код модели, инженерный номер | `description`: «Описание:» (Ford), «Модель:»/«Код назначения:» (Subaru), таблица «[Наименование] [Прим.]» (VW/Skoda); иначе `notice`, если он не повторяет название | `note` |
| Даты выпуска | «Дата производства: 29/09/2014 - 05/10/2018» (Ford, Subaru), «Диапазон от:» (Hyundai) | `appliesPeriod` |
| Количество | «Кол-во деталей: 04», последняя цифра строки таблицы VW/Skoda | `quantity` |

Повод: у Ford Mondeo под позицией 10655 пять АКБ одним названием «Батарея аккумуляторная»,
ёмкость (43/60/70/75/80 Ah) была только в `description`, и мастер выбирал по шильдику старого АКБ
в чужом каталоге. Если в выдаче несколько номеров одной позиции (`partsWithVariants` в
контрактах), бот и веб показывают примечание каждого и просят сверить с тем, что стоит на
машине. Мобильное приложение примечаний пока не показывает вовсе — у него своё зеркало контрактов.

**Покрытие по VIN (таблица вендора, 23.09.2026).** Менеджер прислал «Каталоги parts-catalogs.com.xlsx»:
78 марок, у каждой — модели, дата актуальности каталога и есть ли пробивка по VIN. Оригинал лежит
локально в `data/` (в git не входит). Каталог у всех марок оригинальный, но у части есть только
поиск «марка → модель → модификация», а базы VIN нет — тогда `/car/info?q=VIN` отвечает `200 []`,
как у Jaguar XF `SAJAA04M6FPU46282` из корзины `catalog:cases`.

| Что | Марки |
|---|---|
| Нет VIN, только марка-модель-модификация | Jaguar (данные 2017-01), UAZ, Belgee, GAC, Tenet, Voyah, Honda Japan, Man, VolvoTrucks, JCB, John Deere, Hitachi, Doosan |
| VIN не определён («?») | Omoda, Tank; у Volkswagen в таблице пусто, но живьём VIN пробивается (Jetta `LFV3B2FY2N3102396`) |
| VIN через «китайский API» вендора | Changan, Chery, Geely, Haval, Lixiang — как устроен этот путь и тот ли это `/car/info`, у вендора не спрашивали |
| Каталог больше не обновляется | Bentley (2010-03), Citroen и Peugeot (2013-11), Hyundai и Kia кроме Кореи, Infiniti и Nissan (2019-02), Isuzu (2018-03), Suzuki (2019-05) |
| Старые данные при живом VIN | Acura 2008-08, MG/Rover 2011-01, Volvo 2014-10, Land Rover 2014-12, Alfa Romeo и Fiat 2014-05, Mercedes и Smart 2018-09, BMW и Mini 2020-01 |

Из этого следует: пустой ответ `/car/info` у марки из первой строки не значит, что машины нет в
каталоге. Искать такие машины придётся по модели и модификации (VIN расшифровывать у другого
источника, например у 17vin), а этого пути в адаптере пока нет. У марок со старыми данными
свежие машины могут не найтись или получить не свою модификацию. По ним нужен другой каталог.

### ABCP / Emex (поставщики, боевые)

Берём цену, наличие, срок, склад, бренд, артикул. Не берём признак невозвратности и
максимальный срок поставки — для заказа это существенно, проверить наличие полей живым вызовом.

### Avtocod (госномер → VIN)

Берём только VIN. Реестр по госномеру отдаёт и паспортные данные машины — марку, модель, год;
сейчас они выбрасываются, и после распознавания номера мы идём декодировать VIN заново.
Ключей нет, адаптер живым вызовом не проверялся.

### vPIC / NHTSA (бесплатный декодер VIN, боевой)

Государственный декодер США, без ключа и договора (`vpic.nhtsa.dot.gov`). Только `decodeVin` —
деталей, номеров и схем у источника не бывает, поэтому в цепочке он последний и с пометкой
`decodeOnly` (в поиск деталей не включается, его «пусто» не маскирует сбой настоящих каталогов).
Берём: марку, модель, год, объём/код двигателя, тип кузова; остальное (~140 полей: привод,
коробка, страна сборки, комплектация) лежит в `vehicle.raw` — в контракт не мапим, пока экран
это не показывает. Ограничение по построению: декодирует по правилам рынка США, европейские VIN
«декодирует» неверно (Mercedes W177 2019 → «2001»), поэтому адаптер сам отсекает VIN без верной
контрольной цифры (9-я позиция, 49 CFR 565) ещё до сетевого вызова. Живым вызовом на боевом
сервере не проверялся (24.09.2026) — проверить при следующем деплое: `smoke:live` или VIN
американской машины в боте.

### Официальные каталоги заводов (не адаптер — подсказка)

`official-catalogs.ts`: для марок, которых нет ни в одном подключённом каталоге с VIN-поиском
(УАЗ XTT, LADA XTA, КАМАЗ XTC — по таблице вендора parts-catalogs от 23.09.2026), бот на
неопознанный VIN отвечает не «проверьте номер», а честной причиной и ссылкой на официальный
каталог завода (docs/FREE_CATALOGS.md, раздел «Заводы РФ»). Ссылки только на заводы и их
официальных поставщиков.

### acat, partsindex, epcdata

Заготовки: имена полей угаданы (`oemNumber`/`oem`/`number`/`partNumber` подряд), живым вызовом не
проверялись, схемы узлов не берутся вовсе. Перед включением любого из них — пройти чеклист
сначала.

## Таблица «деталь → узел» (parts-catalogs, 23.09.2026)

Поиск по похожести слов чинился по одной жалобе и давал 61% верных ответов на замере
(`catalog:benchmark`: 149 ходовых запросов × машины пилота). Теперь parts-catalogs сначала
ищет по таблице `backend/src/catalog/part-nodes.ts`:

- **Коды справочника общие для всех марок.** Помпа — код 130 и у Subaru, и у Chery (1394 кода,
  у каждого одно название). Строка таблицы: формулировки мастера → коды → листья дерева, где
  деталь лежит → запасной шаблон названия для деталей без кода (Subaru и Toyota кодируют лишь
  15–17% деталей, остальное по-английски).
- **Деталь с чужим кодом не бывает ответом** ни в поиске по таблице, ни в поиске по словам
  после него. Лучше честное «не найдено», чем свеча зажигания на «свечу накала».
- **Строка выбирается по запросу мастера, а не по варианту из словаря жаргона**: сервис передаёт
  исходный запрос (`searchParts(vehicle, variant, original)`), иначе «датчик коленвала»
  через вариант «коленчатый вал» находил сам вал.
- **Деталь — первое слово запроса**, перед ним допустимы только прилагательные: «шкив коленвала»
  в строку «коленвал» не попадает и уходит в прежний поиск по словам.

Листья в строках подобраны по слепку каталога 11 машин пилота (все листья → схемы → детали,
только чтение). Новую деталь добавляют строкой: код — из ответа `parts2` (`nameId`), листья — где
этот код лежит у машин пилота. После правки таблицы — `bun run --cwd backend catalog:benchmark`
(цифра до/после) и `catalog:cases`.

Замер 24.09.2026: 61% → 79–80% верной детали первой строкой, чужая деталь 6% → 0–1%; остальное —
честное «не найдено» (детали нет у машины или в данных каталога, Chery — нужен 17vin).
